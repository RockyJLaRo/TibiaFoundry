# Known Limitations and Uncertainties – Tibia Foundry 7.0.1

## 1. Functional limitations

| # | Limitation | Impact | Workaround / note |
|---|---|---|---|
| L1 | The *DefaultStartPhase* and *RandomStartPhase* filters of 1.x are not offered. | The appearances schema has no start-phase fields, so these filters never worked in 1.x either (B45). | None needed with current client data. If CipSoft reintroduces the fields, the schema in `Core/Protos/appearances.proto` must be extended. That changes the JSON export, so the parity test must then be updated deliberately. |
| L2 | *Generate Lua data for all NPCs* and the Item Catalog's TibiaWiki import depend on TibiaWiki: its availability and how it describes items. | 2.1 uses the MediaWiki API, a 24 h cache and the last good copy, with a notice, when the wiki fails. A change that yields fewer than 1,000 IDs is rejected, not used. On 2026-10-12 the old `action=render` fallback was blocked for programs by a Cloudflare browser check. Since 2026-10-15 the wiki cannot build the "Item IDs" page in time (503 on every request); 7.0.1 reads the item articles the page is made of instead (about 190 requests, about a minute), with the page as fallback. If the wiki changes the query of that page, the articles must be followed (`11_Maintenance_Guide.md` §7.1). | Without a cache, an outage means no fresh list until the wiki answers. The page URL can be edited in the Tools tab. Repair: `11_Maintenance_Guide.md` §7. |
| L3 | Output is defined by the current Tibia client format: protobuf schemas recovered from 1.8.0.26867, CIP LZMA sheets, sprite types 0–3. **No guarantee is given that a future Tibia update will not break a feature.** | 2.1 detects new or retyped fields, unknown sprite types, undecodable sheets, damaged files and missing content. It cannot *read* a format it does not know. | Update procedure: `11_Maintenance_Guide.md` §3–§5. | L4 | GIF and outfit output deliberately differs from 1.x in documented bug fixes (B19 transparent frames, B31 Latin-1 names, B23 areas). | Diff tools comparing old and new exports will show these lines. | Intended. |

| L8 | HR maps are composed in memory as one image. | At 100 % zoom, a full map needs a large amount of RAM (not measured on low-memory machines). | Use 25 % or 50 % zoom. 2.0 is 64-bit, so it is not limited by the 32-bit address space that constrained 1.x. |

| L10 | Validated client versions: 15.33.b21348 (live, full parity), 15.33.9d148f (7.0; its data files are byte-identical to 15.33.b21348), 15.33.c9e45e (8.0; byte-identical to 15.33.9d148f except `package.json`) and 15.25.0e418e (test server, compatibility check and loading only). | Other versions are reported as *Unfamiliar but compatible* when every check passes. | Add versions after the checklist in `11_Maintenance_Guide.md` §3. |
| L11 | Parity references exist only for client 15.33.b21348. | L12 | Attribution is metadata. It is embedded in two places (PNG text chunks and XMP; GIF comment and XMP) to survive ordinary editing. See `13_Branding_and_Attribution.md`. |
| L13 | JSON exports, tab-separated tables, clipboard text and verbatim client files (sounds, LZMA decode, downloads) carry no attribution. | Those files cannot be traced to their exporter. | These formats have no metadata facility, or must stay byte-identical. The status message says so after data exports. |
| L14 | The default creator name is RockyLaRo on every installation of this build. | Exports by other people are attributed to RockyLaRo until they set their own name. | The first start shows a notice; *Settings → Creator attribution*. |
| L15 | Clipboard copies of images keep attribution only in the "PNG" clipboard format. | Apps that paste the bitmap format lose it. | Save to a file, or paste into an app that accepts PNG. |
| L16 | No separate Tibia Foundry logo was supplied. | The official logo supplied for Tibia Forge (it contains no text) is used for Tibia Foundry. | Replace `Assets/Branding/tibia-foundry-logo.png` and run `tools/branding/make_branding.py` (see `13_Branding_and_Attribution.md` §13). |

## 2. Verification gaps

These were **not** executed and are therefore not claimed (see Testing Report §4):

* display scales other than 100 %, per-monitor DPI changes while running, multi-monitor placement restore;
* Windows 10, other Windows 11 builds, other hardware;
* screen readers and Windows high-contrast mode (automation names are set, but untested);
* audible playback, clipboard contents;
* the *Download list* tool against the real test server (mocked only);
* a **real Tibia client update** while the program runs (simulated in tests);
* future Tibia data formats (synthetic changes only; nothing about real future formats is assumed);
* UI wiring of *Crop Cyclopedia*, *Compare Folders*, *Advanced Tools* (sheet builder, slicer, download) and House *Copy/Save* (core logic tested where noted).
* **6.0**: display scales other than 100 % for the theme editor and the Diagnostics page; screen readers on the new pages; a real OneDrive-redirected Documents folder (redirection to another drive, `F:\Users\Rocky\Documents`, was verified, and the resolution goes through the same Windows API); Windows 10.
* **7.0**: the XLSX files in spreadsheet programs other than Excel (only Excel and openpyxl were used); locating client files on a network or removable drive that is disconnected while running (simulated with a missing folder); display scales other than 100 % for the new pages.
* **5.0**: loading converted Tibia.dat/Tibia.spr files in a real 10.98 game client or a legacy-format viewer; exchanging `.aec` packages with Arch-Mina's Assets Editor; opening an RCC file edited by Tibia Foundry in the Tibia client (only Qt's lookup was reproduced and checked); the Assets Editor's output loaded by the Tibia client (only read back and validated by Tibia Foundry); drag and drop in the RCC Editor (handler code tested indirectly through `ReplaceWith`); taskbar flashing and completion sounds (only the threshold logic is tested); interface sizes other than 100 % and 125 % (rendered once each).

## 3. Environment issue observed on the build machine

During UI testing, the Windows session's **window-class (user atom) table** was nearly exhausted: only a few hundred of 16,384 slots were free, and the number fluctuated. Windows then intermittently refused to create windows ("Not enough memory resources are available to process this command").

* An early test run of 2.0 (crash loop, since fixed) and a WPF threading defect (since fixed) contributed load.
* The table was also churning while the program was not running. The exact consumer cannot be identified from user mode.
* **Effect**: any program, not just this one, may occasionally fail to open a window until the session is reset.
* **Fix**: sign out of Windows and back in, or restart. Recommended before further UI testing on that machine.
* **Still present on 2026-10-12** (between about 200 and 480 free slots during the 2.1 work). It caused one 2.1 test-infrastructure hang (A31, fixed); UI tests now skip with the reason instead of hanging.
* **2026-10-13 (5.0)**: 571 free slots before the UI runs; no window was refused.

## 4. Uncertainties about the original

| # | Item | What is known | What is not |
|---|---|---|---|
| U1 | ClickOnce update behavior | The deployment manifest enables install (v1.8.0.0). | Whether an update URL was ever used; not reproducible offline. |
| U2 | Intended use of the `clientbg` and `pbbg` resources | Both are embedded but never referenced (`pbbg1` is the House Images background). | Whether they were planned for a feature. |
| U3 | The original's intent for the start-phase filters | The UI exists and the data do not. | Whether they once worked with an older schema (likely, given the field gap in the schema). |
| U4 | Exact GDI+ rounding for semi-transparent pixels | 70 of 223,694 sprites differ by 1 premultiplied level. The rebuild keeps exact client values. | Nothing; this is GDI+ behavior and the rebuild is the more accurate one. |
| U5 | Original behavior on non-English Windows | It used the current culture for casing and sorting. | Whether wiki editors relied on locale-specific output. The rebuild uses invariant casing (B34) and an NLS-compatible sort that reproduces the original's English ordering. |

## 5. Deliberate design changes (not limitations)

* One resizable window with a navigation rail replaces the fixed tab layout. The *Compare DAT files* window became a page; the hidden tabs became *Advanced Tools*.
* Settings moved from next to the EXE to `%APPDATA%` (1.x settings are imported).
* Sprites no longer need to be pre-extracted (folder, then client, by default; the 1.x behavior is selectable).
