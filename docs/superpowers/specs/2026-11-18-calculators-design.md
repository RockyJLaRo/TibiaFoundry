# Tibia Foundry calculators – design (18 November 2026)

Status: draft for approval. Source material: `docs/redesign/future-feature-roadmap.md` (backlog #1–#11),
`docs/redesign/tibia-tools-ecosystem-research.md` (tested competitors), raw tests in `Work_Redesign\research\calc-tests\`.

## 1. Intent

Add Tibia calculators to tibiafoundry.com so that the site becomes **(a) a place players open every day** and
**(b) the most trusted source of Tibia numbers**. The owner's two hard requirements:

- **Easy on mobile** – every tool fully usable one-handed on a 360 px phone.
- **Correct output, or it does not ship** – "if the tools don't output correct data they're trash".

Research found the gap this fills: the popular calculators agree on skill maths but disagree on gold cost by up to 25 %
because they hide their price assumptions; generic calculator sites are ad-heavy and unsourced; some planners overflow
phones (914 px). Nobody shows formula, source and "checked on" date together.

## 2. Goals, non-goals, anti-goals

**Goals**
- A shared calculator system (one look, one behaviour) and a formula registry with sources, dates and test values.
- First tools chosen for daily return and verifiable correctness (section 5).
- Every result explains itself: formula in words, source link, Tibia version / "checked on" date, any assumed prices
  visible and editable.
- 5 languages, light/dark, 360 px phones, keyboard and screen reader, from day one.

**Non-goals (this design)**
- Wheel of Destiny, Exaltation Forge, hunting-places database, Char Bazaar/market history, charm comparison,
  offline/PWA mode, event calendar (roadmap #16–#23).
- Accounts, logins, servers or databases. Everything runs in the visitor's browser.
- Boss spawn predictions of any kind.

**Anti-goals (a failure even if it "works")**
- A number that differs from the real game, or a formula shipped without independent verification.
- Hidden assumptions (prices, loyalty, events) that change the result without the player seeing them.
- Horizontal scrolling, tiny inputs or sliders that are fiddly on phones.
- Ads, trackers beyond the existing opt-out-able Google Analytics, or third-party coin-seller links.
- Any change to `games/`, `pokemon/`, `tools/`, `.github/`, `CNAME`, `robots.txt`.

## 3. Constraints

- Static site built by `website/build_site.py` from `src/registry.json`, templates and 5 locale files; deployed to the
  GitHub Pages repo only via `scripts/deploy_site.py`, and only after the owner approves each deploy.
- No framework or bundler (plain JS, as today). Lucide icons from the existing sprite (add new ones via `art/icons.py`).
- Fansite Agreement: no CipSoft graphics hosted, no claim of official status, Tibia.com/CipSoft credit (already in footer).
- Privacy: nothing personal in URLs; any `localStorage` key must be listed on the Legal page.
- Release builds need `--checksums <Release/9.0.5/SHA256SUMS.txt>` (otherwise the Downloads page loses SHA-256/sizes).

## 4. Approaches considered

| | Approach | Trade-offs |
|---|---|---|
| **Chosen** | **One real page per calculator** (`/calculators/experience/`, ×5 languages) generated by `build_site.py`, sharing one script and one formula registry | Bookmarkable, indexable by search engines (key for becoming the trusted source), fits the existing builder; a little more build code |
| Rejected | Hash routes inside the Tibia tools app (`#/calc/experience`) | Least code, but search engines see one page – calculators would be nearly invisible in search |
| Rejected | A framework (React/Svelte) | Faster form code, but adds a build step and dependencies the site has never needed; no player benefit |

The owner chose the recommended approach (18 Nov 2026).

## 5. Scope and order

Built in batches; each batch is tested, reviewed by the owner and deployed only on approval.

**Batch 1 – foundation and daily quick wins**
1. Calculator system + formula registry + verification tests (roadmap #1, #2).
2. **Experience & level** with **party share range** (#3, #11).
3. **Stamina** (#6).
4. **Blessings cost** (#9).
5. **Character stats** – HP, mana, capacity by level and vocation (#10).
6. **"Today in Tibia" extended** – server-save countdown and Rashid's location, on the home page and the calculators hub (#7).

**Batch 2 – high-value, more complex**
7. **Exercise weapons** with editable NPC and Tibia Coin prices (#4).
8. **Party loot splitter** from the in-game Party Hunt Analyser text (#5).

**Later (separate design):** imbuement cost (#8), boss kill statistics view (#14), character progress (#12),
compare two characters (#13).

## 6. Correctness: the verification standard

A calculator ships only when its formula passes all of these. This is the core of the design.

1. **Source of the rule.** Official CipSoft material (Tibia.com manual, news) first; otherwise TibiaWiki (EN), cited with
   the page URL and the date read. Every source is stored in the registry.
2. **Independent test values.** At least **3 known input → output pairs per formula**, including edge cases (level 1/8,
   boundaries such as stamina 39:00 and 42:00, vocation "none"). Each value states where it comes from:
   - an official example, or
   - a published value from a second independent source (e.g. a TibiaWiki table), or
   - the same result from **two independent established calculators**, recorded like the existing
     `research/calc-tests/` captures.
   **No in-game checks** (owner's decision, 18 Nov 2026): only published sources and other calculators are used.
   A formula with only one source and no agreeing second one **is not shipped**.
   Values the builder computes from the same rule the code implements do **not** count as independent (that would
   test the code against itself). A published rule plus one independent value is the minimum per formula; the 3 test
   values may then include computed edge cases.
7. **All or nothing per calculator** (owner's decision, 18 Nov 2026): a calculator goes live only when **every** part
   of it passes (every vocation, every blessing type, every option). If one part cannot be verified, the whole
   calculator waits; the rest of its batch can still ship.
3. **Automated tests.** The test values live in the registry; a Node unit test runs every formula against them, and the
   build (`--strict`) fails if any calculator lacks a source, a "checked on" date or 3 test values.
4. **End-to-end check.** A Playwright check types the test inputs into the real pages (all 5 languages, 360 px and
   desktop) and compares the displayed, locale-formatted result with the expected value.
5. **Visible provenance.** Under each result: "How this is calculated" (formula in words), source link, "checked on
   <date>". After each Tibia update, entries for changed systems are re-checked and the date updated.
6. **Known values already verified:** experience 100→200 = 113,695,000 (`50/3·(L³−6L²+17L−12)`, matched by TibiaRoute);
   stamina 39:00→42:00 = 18 h offline (TibiaPal only so far – a second source is still needed); exercise Knight melee 100 (100 % left)→110 = 586,000 charges
   (TibiaRoute, TibiaPal and Exevo Pan agree; TibiaWatch +0.35 %). Other formulas are verified during implementation
   under rules 1–2 before their page is built.

## 7. How it works

### Pages and navigation
- New hub page **Calculators** (`/calculators/`, icon `calculator`) in the header next to "Tibia tools" and in the
  menu; one card per calculator (icon tile + one-line purpose), plus the extended "Today in Tibia" panel.
- One page per calculator: `/calculators/<slug>/` in all languages (`/de/calculators/…` etc.), breadcrumbs
  Home › Calculators › <name>, own title/description/hreflang/sitemap entries.
- The home page "destination" cards gain a Calculators card.

### Data and code layout
- `src/registry.json` → new `calculators` list: `id`, `slug`, `icon`, `template`, `formulas` (ids), `batch`.
  `build_site.py` turns each into a page (placement: none) and builds the hub.
- `src/formulas.json` → the formula registry: per formula `id`, `title` key, `rule` (formula in words, locale key),
  `sources` [{url, kind: official|wiki|calculator, read}], `tibiaVersion`, `checkedOn`, `tests` [{in, out, from}].
- `src/js/formulas.js` → pure functions, no DOM; written so the browser and Node tests load the same file.
- `src/js/calc.js` → shared page behaviour: reads inputs, validates, calls the formula, renders results, share link,
  copy, reset, remembered prices.
- `src/templates/calc-<id>.html` → the inputs and result layout of each calculator using shared components;
  `calculators.html` → the hub.
- Locale keys under `calc.*` in all 5 locale files; `tests/check_i18n.py` keeps them complete.

### Behaviour (every calculator)
- Results update as you type (no submit button); announced politely to screen readers.
- Inputs accept the **page language's** number format and Tibia shorthand: `1.5kk`, `250k`, `1 500 000`
  (builder's call: the page language decides, not the browser locale). Level/skill fields accept whole numbers only.
  Every interpreted number is echoed under its field ("read as 1,500,000"), so a misread is visible; input that fits
  neither the page format nor shorthand gets an inline error instead of a guess.
- Clear inline errors in plain words ("Target level must be higher than current level").
- **Share link** puts only calculator inputs in the query string (`?from=100&to=200&exph=1.5kk`); opening it fills the
  form. The loot splitter has no share link (its text contains character names).
- **Copy result** button (plain text, ready to paste in game chat or Discord).
- **Reset** returns to defaults.
- Prices the player enters are remembered on that device only (`localStorage` key `tf-calc-prices`, listed on the
  Legal page); defaults are labelled with their date and source.

### Mobile layout (360 px first)
```
┌ Experience & level ────────────┐
│ Current level   [ 100 ]        │   one column, 44 px touch targets,
│ Target level    [ 200 ]        │   numeric keyboard (inputmode)
│ Exp per hour    [ 1.5kk ]      │
│ ─────────────────────────────  │
│ 113,695,000 exp needed         │   main answer large, first
│ ≈ 75 h 47 min of hunting       │
│ Party share range: 67 – 150    │
│ [Copy]  [Share link]  [Reset]  │
│ ▸ How this is calculated       │   collapsed on phones,
│   rule · source · checked on   │   open on desktop
└────────────────────────────────┘
```
Desktop: inputs left, results right (two columns from 768 px). No sliders; steppers only where they help (levels).

### Per-calculator notes
- **Experience & level:** current level (+ optional % to next), target level, exp/hour, hours per day → exp needed,
  hours, days, estimated date; share range for current and target level.
- **Stamina:** current and target stamina (hh:mm) → offline time needed and the local clock time it is reached.
- **Blessings:** level → price per regular blessing, per enhanced blessing, total, with/without Inquisition.
- **Character stats:** level + vocation → HP, mana, capacity (and the level-8 vocation start rule). All current
  vocations including **Monk** are in scope (builder's call), each under the same verification standard.
- **Today in Tibia:** server save at 10:00 Europe/Berlin (CET/CEST handled by `Intl`), countdown in the visitor's
  local time; Rashid's town by weekday, switching at server save. Tested across both DST changes.
- **Exercise weapons (batch 2):** vocation, skill, current/target, % to next, loyalty, dummy (normal/house), double
  event → charges, weapons per type, cheapest mix, time, cost in gp **and** TC; NPC price and TC price editable.
- **Loot splitter (batch 2):** paste the Party Hunt Analyser text → each player's balance, the fair share and the
  fewest transfers ("transfer 1,234,567 to Name"), copyable; optional extra costs per player. Parsed entirely in the
  browser; clear message when the text format is not recognised. Verified by feeding the same real analyser texts
  (several party sizes, one with a negative balance) to two established splitters and matching their transfers.
  **Prerequisite:** real analyser texts must come from published sources (no in-game capture); if none are found
  before batch 2, the loot splitter waits.

## 8. Testing and release gates (each batch)

- Strict build; locale parity (5 languages); Node unit tests for all formulas (registry test values); new Playwright
  check `calculators` (values, share links, copy, errors, keyboard, aria, 360 px no overflow) plus the existing 14 checks;
  screenshot matrix extended with the calculator routes; contrast unchanged (existing tokens only).
- Owner reviews screenshots and tries the pages before any deploy; deploy via `scripts/deploy_site.py` with checksums.
