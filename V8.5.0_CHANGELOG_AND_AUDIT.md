# Tibia Foundry 8.5.0 — Changes, audit and verification

Date: 2026-10-22. Starting point: the 8.0.0 source in this folder. Settings, archives, revisions and file formats are unchanged; 8.0.0 and 8.5.0 can use the same `TibiaFoundry-Data` folder.

## Release notes (for users)

**A clearer archive confirmation.** Archiving a client (Clients → *Archive…*, or *Check for changes* → *Archive…*) now opens a dedicated dialog instead of a block of text:

* the client, server and version in the title;
* three figures at a glance: **Files**, **Archive size** (the files as restored) and **New disk usage** (what is actually written — contents already archived are reused);
* **Personal data** in its own section. *Include personal data* applies to this archive only; the figures are recalculated on the spot, and *Archive* archives exactly what is shown;
* **File details** (collapsed) lists every category — client files, options and hotkeys, character data, explored map, screenshots, logs… — as *Archived*, *Left out* or *Not archived*.

**Fixes and polish**

* *Check for changes* → *Archive…* reads the client once instead of twice (a full read of every file was repeated).
* Dialogs stay within the screen on small displays and at high display scaling; long messages get a wider box.
* Error messages show the reason in plain words and point to Diagnostics → Log for technical details.
* Clearer rebuild confirmation, with a button that says what it does (*Rebuild installation* / *Restore folder*).
* Download-limit messages show sizes in MB instead of raw byte counts.
* Closing Tibia Foundry while an archive or another operation runs now asks first.
* The "not archived yet" notice disappears as soon as the client is archived from the Clients page.
* Pressing Esc on an import question (Assets Editor, RCC Editor, Item Catalog items.xml) now cancels instead of importing.
* No tool can write into a Tibia client folder or the client archive, also when the folder is typed.
* *Import settings* and *Reset all settings* no longer move where your client archive is (or which revision is in use).
* Assets Editor: a failed or cancelled *Save as* leaves no half-copied folder; the status after saving is readable again.
* Item Catalog: an invalid import is refused before anything is written.

**Compatibility:** nothing to do when upgrading from 8.0 — replace the program and keep `TibiaFoundry-Data`.

## 2. Architecture as found (summary)

* `TibiaFoundry.Core` (domain: clients, archive store, formats, settings, diagnostics), `TibiaFoundry.App` (WPF, CommunityToolkit MVVM; view models drive dialogs through `IDialogService`), `TibiaFoundry.Tests` (xUnit v3, view-model tests with `FakeDialogs`).
* One version source: `src/Directory.Build.props` (`Version`, `FileVersion`, `InformationalVersion`); `AppIdentity.Version` reads the assembly attribute; the About page, logs, self-test, diagnostics reports and archive manifests (`ImportedBy`) use it. Tool manifests carry their own tool versions (`"8.0"` for Clients and the Rebuilder — the version the tool was introduced, left unchanged).
* Size formatting is already centralized in `ReportWriter.FormatSize` (binary units, "0 bytes" for zero, 3 significant digits); no competing formatter was found in user-facing code.
* Long operations go through `PageViewModel.RunAsync` (busy state, cancellation, operation slots, job history, error reporting); re-entrancy is blocked by `IsBusy`.

## 4. The archive confirmation (redesign)

**Before:** a `MessageDialog` with one paragraph: scope, storage, "N files, X; Y new on disk", and every exclusion rule with counts on one line, plus *Archive* / *Include personal data too* / *Cancel*; choosing the second option opened another confirmation.

**After:** `Views/Dialogs/ArchiveDialog.xaml` (shown through `IDialogService.ConfirmArchive`):

| Section | Content (all from the scan and the store) |
|---|---|
| A. Header | *Archive <client>*; server · version; the folder (trimmed, full path in the tooltip) |
| Warning | Only when kept as an incomplete revision: how many entries are not archived |
| B. Summary | Tiles: Files · Archive size · New disk usage. Below: Scope, Storage (with where to change it), Reused (shared storage only), Changes against the newest revision |
| C. Personal data | State (left out with files/size, included, or "this folder has no personal data"); the *Include personal data* check box (Alt+I) with what it covers and the privacy note; progress while the folder is read again |
| D. File details (collapsed) | Category · Status · Files · Size · New on disk, for every included category, every exclusion, and unreadable entries (first 8 listed) |
| E. Actions | Cancel · **Archive** (default, Enter); Esc cancels and also stops a recalculation |

**Domain model:** `Core/Clients/ArchivePreview.cs` and `ClientStore.PreviewArchive`. It separates the size as restored (`LogicalBytes`), what is written (`NewBytes` — the same rule as the free-space check: shared storage writes each content once and only when the store lacks it; independent storage copies everything) and what is reused. Category sums equal the totals. A file of a personal folder that the client's own lists name is kept even without personal data and is shown as "Options and hotkeys (listed by the client)", so it is not confused with the left-out part of `conf/`.

**Behavior kept:** the default comes from Settings → Tibia client → *Include personal data*; ticking the box in the dialog applies to this archive only and does not change the setting (tested). The consistency question ("Read it again" / "Keep as incomplete revision") still comes first; if the folder changed while it was read again for the personal-data option, that question is asked again before anything is archived.

## 5. Other UI and message changes

* `MessageDialog`: messages longer than 480 characters or with lines over 110 characters use a 580-DIP box instead of 460.
* `DialogService.ShowError`: shows the message and the exception's own text (not its type); repeats nothing already in the message; names Diagnostics → Log. The type and stack trace are still logged.
* Rebuilder confirmation: target and files on labeled lines; the confirm button is *Rebuild installation* or *Restore folder*.
* `HttpFetcher`: size-limit errors use `ReportWriter.FormatSize`.
* Message boxes without a title showed "Info" or "Warning" as the title; they now show "Tibia Foundry".
* Every confirmation was checked to use specific button labels (none relies on a bare OK/Cancel).
* Byte counts that remain in exact form (`ContentStore` verification, LZMA/RCC format errors, self-test lines) are diagnostics where the exact number matters; left as they are.

## 8. Audit coverage and known remaining issues

**Reviewed in depth:** the archive flow end to end (Clients page, background archive after the launch check, first-run setup, `ClientInventory`, `ClientStore.Archive`/`NeededBytes`/`EnsureSpace`, `CopyStore`/`DeleteStore`, incoming-journal recovery), the Rebuilder, the dialog service and every dialog window, size formatting, version sources, global exception handling, `async void` handlers, and empty `catch` blocks.

**Reviewed in a second pass (every view model and its write paths):** Assets Editor (and `AssetsProject.Save`), RCC Editor, Item Catalog (and `ItemCatalogStore` writes), Scripts (and the shared removal/backup engine), Map tools, House images, Sounds (and `AudioPlayer`), Sprite extractor, Client Converter, Appearances, Outfitter, Static data, Compare, Compatibility, Advanced tools, Settings (import, reset, folders), Theme Editor, Diagnostics, About, the main window's closing. Also: every place that writes outside an operation wrapper, every confirmation's button labels, and every output folder check.

**Not reviewed line by line:** the binary format code in Core (LZMA encoder/decoder, protobuf schemas, RCC format, legacy `Tibia.dat`/`Tibia.spr` codec, sprite sheet decoder, GIF/PNG writers). It is read-only parsing and encoding covered by byte-for-byte round-trip and parity tests; earlier audits (`docs/09_Stability_Audit_Report.md`) cover it.

**Known, not changed (recommendations):**

* First-run setup (step 4 of 4) still asks to archive with a short text confirmation and archives with the personal-data setting; it does not use the new dialog. It is a wizard step with its own summary; switching it would change the setup flow.
* The archive started from the start-up notice (*Archive* above the status bar) runs in the background without a confirmation, as designed in 8.0 (it uses the settings shown in its tooltip).
* Recalculating the personal-data option inside the dialog is not listed under Diagnostics → Operations (the dialog shows its own progress).
* Many messages use "file(s)"-style plurals; left as they are.
* With *Include personal data*, screenshot-named files outside the `screenshots` folder are listed under "Client files" in File details (they are categorized by folder); the totals are right.
* An archive interrupted by closing the program leaves its unfinished files in the archive's `Incoming` folder until the archive is next opened, which removes them (by design: nothing unfinished is ever published).
* The dialog-height cap is verified by a unit test and a simulated small-screen render, not on a physical small or high-DPI display.
