# Tibia Foundry 8.6.0 – changes, audit and verification

Release date 2026-10-25. Source: `Source_History/src-8.6.0/TibiaFoundry-8.6.0-source` (copied from 8.5.0, which stays untouched in `src-8.5.0`). The short list is in [CHANGELOG.md](CHANGELOG.md).

## 1. Version

**8.6.0.** The Universal File Metadata Viewer and Editor is included as a working, tested feature (53 tests on real files; editing verified for every editable extension), so this is a feature release rather than 8.5.1. Changed: `src/Directory.Build.props` (Version, FileVersion, InformationalVersion → About page, diagnostics, attribution, `AppIdentity.Version`), `Portable.pubxml` (output folder), README, README-Portable, CHANGELOG, docs 18 and 22, the website. Historical references (8.5.0 entries, settings format numbers, compatibility identifiers) are unchanged.

## 2. Setup completion dialog ("Tibia Foundry is set up")

Before (8.5.0): one paragraph of mixed facts — `docs/screenshots/8.6.0/before_setup-summary_8.5.0.png`.

After: `IDialogService.ShowReport` with a heading, a one-line summary and five sections (`ClientStartup.Summary`):

| Section | Content (runtime values) |
|---|---|
| Active client | client label (Default Live Client…), server, version (warning color when unknown), status (complete installation in green, otherwise "usable, not a complete installation"), checked at every start |
| Installation | folder in a monospaced, selectable field with a copy button; files and size |
| Archive and storage | the actual outcome: *Archived as "…" (n files)* in green, *Not archived yet* with where to do it, or *Not archived: <reason>* in red (the section turns red too); new-archive storage; personal data; archive folder |
| Other default clients | the other default client's real state (available with version, or not installed / incomplete…) |
| Next steps | where to change the client, storage, the start check, and how to run setup again |

*Copy details* copies everything as text. The dialog is resizable, scrolls on small screens (snapshot: fits a 1093×576 work area), and works at 440 px width (paths wrap).

After: `docs/screenshots/8.6.0/after_dialog_setup-summary_{dark,light}.png`, `…-narrow_dark.png`, `…-small-screen_light.png`, `after_dialog_setup-summary-not-archived_light.png`.

## 3. Archive decision (setup 4 of 4)

Before: `before_setup-archive-question_8.5.0.png`.

After (`ClientStartup.ArchiveQuestion`): heading *Archive this installation now?* and what archiving does (keeps this version after launcher updates; the Rebuilder can make a folder from it), then:

| Section | Content |
|---|---|
| Client to archive | client, server, version, what it is, files and size, folder; entries that could not be read (when there are any) |
| Left out: personal data | how many files, that they stay in the client folder unchanged, a table per category (files, size; an empty category says "none"), how to include them. When personal data is included in Settings, the section says so instead. |
| Storage | mode in words, disk space needed (shared: "up to"), archive folder, free space on its drive (red when smaller than the client) |
| If you choose Not now | nothing is archived or written; the client stays usable; Archive… on the Clients page; what the check at the next start does with the step-3 choice (ask, or archive automatically) — verified in `MainViewModel` |

Verified behavior of excluded data: personal data is never archived unless *Include personal data* is on, and Tibia Foundry never writes into a client folder, so "they stay in the client folder, unchanged" is exact. Buttons keep their meaning: *Archive now* / *Not now* (Esc = Not now). A failed archive is reported in the summary, not in a separate box.

## 5. Default Live Client and Default Test Client

* `Core/Clients/DefaultClients.cs`: `<packages>\Tibia` (live) and `<packages>\<test package>` (default `TibiaExternal`), where `<packages>` is the packages folder chosen in Settings or `%LOCALAPPDATA%\Tibia\packages` from Windows' known folder (`Environment.SpecialFolder.LocalApplicationData`). On this PC it resolves to exactly `C:\Users\Rocky\AppData\Local\Tibia\packages\Tibia` and `…\TibiaExternal` (asserted by a test that runs only on this profile). No source file contains a user name (also asserted).
* Each folder is classified by its files with the existing `FolderInspector` (complete installation, usable, incomplete, not a client, missing, cannot be read); version from the existing version evidence.
* Setup: both defaults first, then any other client found; browse for any folder; a choice made before is replaced only after a confirmation; the live/test-server selection mechanism and storage of the choice are unchanged.
* Tests (`DefaultClientTests`, 13 cases): both present; only live; only test (set up as the test server); neither; incomplete and foreign folders; unknown version; custom folder with spaces, brackets and `#`; another profile with non-ASCII characters; invalid path; an earlier choice kept or replaced with consent; the report text form.

## 6. File Metadata

See [docs/22_File_Metadata.md](docs/22_File_Metadata.md) for formats, capabilities, the save procedure, warnings, recovery and limitations. Architecture: `Core/FileMetadata` (`IMetadataProvider` per format family declaring capabilities and limitations; `MetadataEngine`; `MetadataBatch`; `MetadataFields`; `FileSystemMetadata`), `App/ViewModels/MetadataViewModel.cs`, `App/Views/Pages/MetadataPage.xaml`, manifest `BuiltInTools.FileMetadata` (navigation, settings, dependency check, Diagnostics), a dependency probe for TagLib#, and a self-test check.

Dependency added: **TagLibSharp 2.3.0** (LGPL-2.1-only, used unmodified). At the owner's request the portable edition bundles it into `TibiaFoundry.exe` like every other library (the folder edition ships `TagLibSharp.dll`). LGPL-2.1 compliance for the bundled copy relies on publishing the source package (`TibiaFoundry-8.6.0-source.zip`) with every release, so users can rebuild with a modified TagLib#; its license text is in `tools/release/licenses/LGPL-2.1.txt` and in `THIRD-PARTY-NOTICES.txt` (generated by `make_notices.py`, which now covers it). About lists it.

A defect of TagLib# found and handled: writing XMP-only fields to a JPEG without EXIF makes TagLib# create an empty EXIF block that it then reads as "possibly damaged". The provider leaves such a block out, and the engine refuses any save whose result a reader finds damaged.

## 9. Known limitations

* File Metadata: PDF, programs, TAR, BMP/WebP/ICO and other raster formats, camera raw files, Monkey's Audio and Tibia client files are read only. Custom Office properties and some format-specific tags are kept but not shown.
* The website's download buttons lead to an empty Releases page until a release is published on GitHub.
* Builds are not code-signed (SmartScreen may warn).
* Assets Editor and Client Converter outputs and rebuilt installations are checked file by file but not in a running game client (unchanged).
